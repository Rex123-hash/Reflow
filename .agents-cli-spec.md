# Objective Recovery - P1A Agent Specification

## Approved scope

Implement P1A only: a canonical typed `DisruptionEvent` published to Google Cloud
Pub/Sub invokes an authenticated Cloud Run service, which durably creates or resumes one
Firestore incident, computes deterministic blast radius, asks a real Google ADK workflow on
Vertex AI Gemini 3.7 Flash for three materially different typed recovery candidates, applies a
typed risk critique, rejects invalid candidates with the deterministic policy engine, selects a
valid candidate, and persists the result.

The terminal state is `PLAN_SELECTED`. The incident must not be resolved and no Calendar,
GitHub, Gmail, authentication UI, bonus model, frontend, or other external side effect is in
scope.

## Runtime and infrastructure

- Existing Python 3.12 `src/` project; preserve all P0 domain behavior and quality gates.
- Google Agents CLI 1.0.0 with stable `google-adk` 2.7.1.
- Vertex AI model `gemini-3.7-flash` at location `global`, after a successful project smoke test.
- One private Cloud Run service in `us-central1`, scale-to-zero, with a low maximum instance cap.
- One authenticated Pub/Sub push subscription plus primary and dead-letter topics.
- Firestore Native mode in `us-central1` as the authoritative workflow ledger.
- Dedicated least-privilege runtime and Pub/Sub-invoker service accounts.
- Terraform owns all custom infrastructure. Cloud Logging JSON events and Cloud Trace provide
  metadata-only observability; prompt/response content capture and BigQuery are disabled.

## Workflow and authority

- Pub/Sub is at-least-once. A transactionally created event claim keyed by canonical event ID
  deduplicates delivery and maps to a stable incident ID.
- The accepted deterministic operational graph computes impact. Gemini cannot change graph or
  policy truth.
- All model outputs use Pydantic schemas before entering deterministic code. Malformed output,
  timeout, or partial planner failure records a safe workflow event and never corrupts state.
- Compare planner designs: three parallel perspective agents, one diverse-bundle planner, and a
  hybrid strategy-seed/plan design. Measure diversity, latency, schema reliability, token cost,
  failure isolation, and demo clarity before selecting the deployed design.
- Planning perspectives are deadline-first, risk-minimization-first, and resource-balance-first.
- The deterministic policy engine owns hard constraints and blocking unknowns. Stable code owns
  selection and restart/resume behavior.
- Persist concise rationale/evidence summaries only; never persist hidden chain-of-thought.

## Required evidence

- Preserve the existing unit, formatting, lint, strict typing, and >=95% coverage gates.
- Add duplicate delivery, Firestore persistence, malformed Gemini output, timeout/failure,
  partial planner success, all-invalid, blocking-unknown, stable selection, and restart/resume

- Run behavioral ADK evaluation and real planner architecture experiments.
- Publish a real event and report exact cloud resources, versions, model, plans, diversity,
